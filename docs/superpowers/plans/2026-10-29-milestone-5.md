# Milestone 5 implementation plan and audit

Base: merged main `63fa86c`. The existing managed worktree is reused; the main checkout and its private inputs remain untouched. Deliver 5A, 5B and 5C as separate stacked reviewable PRs, with no automatic merge. Later PRs target their prerequisite branch until it is merged, so their diffs stay focused.

## Audit

- Existing React/TanStack Query, URLSearchParams/History, AbortSignal, labelled controls, freshness/error/offline components and Toronto conversion utilities are reusable. Baseline production app inspected with synthetic browser fixtures; private captures/database are not accessed.
- Current API room schedule returns meetings and a single conservative coverage summary. Its bounds can enclose gaps, so they cannot be used to paint free time. Add server-derived day periods and retain the old fields.
- Current availability verifies only a 5–240 minute request and supplies a next booking, not a contiguous free-until bound. Keep that contract intact; introduce a bounded room-search contract for richer server-owned search/status calculations.
- Strict ingestion and MeetingOccurrence intentionally omit descriptions. Existing public API provides only timing/status. No source labels are authorized for this work. Use Scheduled event; an optional explicitly approved label type may be designed without changing storage or importing descriptions.
- Database publication, lifecycle, migrations, parser, seed and raw snapshots are out of scope. New endpoints use get_read_session's read-only repeatable-read transaction and one captured dataset.

## 5A: design, theme, time and identifiers

Files: frontend/src/{App.tsx,App.css,index.css,components.tsx,time.ts}, new theme.tsx/preferences.ts/rooms.ts/ui.tsx, index.html, frontend tests/README.

Use existing card/button/notice patterns rather than a UI framework. Compact campus-signage layout: canvas #eef3f5, surface #ffffff, ink #102f3c, teal #08766e, blue #245acc, amber #684300; dark canvas #101d25, surface #172a34, ink #e4eef1. Central semantic CSS variables cover every state.

Persist only safe local preferences. Apply Light/Dark/System before initial paint, with OS fallback and blocked-storage tolerance. Central roomLabel uses backend building_code + room_number. Keep legacy room/date/query deep links and focus/back behavior.

## 5B: room and building calendars

Files: backend/app/{main.py,schemas.py,services/calendar.py}, additive room_schedule integration; frontend/src/{api.ts,App.tsx,navigation.ts}, new Calendar.tsx/BuildingSchedules.tsx, styles/tests/docs.

Add validated building/day endpoint (one building, one campus date, bounded room/meeting payload, constant batch queries). Return building, date, query, common display window, rooms with room metadata, meetings, coverage windows and server-derived available/scheduled/unknown periods; one dataset/freshness. Room schedule receives the same additive day-period fields. Unknown/partial coverage subtracts from complete coverage; cancelled meetings do not occupy time. Window reflects actual intersecting coverage/meetings, falling back to the calendar day when unknown. Use UTC geometry so DST, midnight and overlaps remain correct. No per-room request fanout.

Calendar blocks are keyboard-accessible interval controls with a dialog and accessible list. Mobile scroll retains aligned room labels. Display preference hides detailed event annotations, never occupied state. Optional public-label type is inactive unless a future explicitly authorized backend supplies it; no label storage or extraction changes.

## 5C: search and local favourites

Files: new backend services/room_search.py and schema/route additions; frontend search.ts/api.ts/components.tsx/App.tsx, new SavedRooms.tsx/favourites.ts, tests/docs.

New bounded room-search endpoint supports offset-aware start and duration or explicit end (5–240 minutes), building, normalized room-name matching, sorting and optional capped room-ID batch. Return current available/scheduled/unknown/inactive state, proven available_until and next known supported start within a bounded 24-hour lookahead. Compute with uninterrupted effective complete coverage and scheduled meetings server-side. Unknown gaps remain unknown; null never means unlimited or impossible. The existing availability endpoint remains compatible. Search/sort/page state lives in the URL; preserve old bookmarks. Local favourites store validated room IDs/building codes only and never cache availability. Saved rooms are checked in one snapshot-consistent batch.
