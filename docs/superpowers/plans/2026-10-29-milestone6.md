# Milestone 6 implementation plan

Goal: import complete authorized weekly exports through the existing audited pipeline, then add a separate private operator dashboard.

Architecture: daily and weekly source adapters share the strict cell-grid validator and normalized Bundle. Existing staging, integrity hashes, anomaly review, source-age checks, and atomic publication remain authoritative. Weekly rooms map by exact manifest labels to stable building/room identities; absent source IDs remain null. A v2 manifest declares format, complete reviewed inventory, explicit week-start/file/capture metadata, target seven days, and per-room expected windows. Daily v1 stays compatible.

PR 1 (`feat/weekly-timetable-ingestion`, base main):
- [ ] Extract and regression-test shared strict grid validation; add independent weekly document/header/caption validation with explicit Sunday week start.
- [ ] Extend manifests and normalization without duplicating staging. Validate every weekly export against declared inventory and room bounds; select target days explicitly; reject ambiguous duplicate source dates.
- [ ] Test synthetic daily/weekly equivalence, rollover, spans, partial inputs, DST, hashes, stage/publish, idempotency, inventory changes, and age regression. Run backend checks and document PowerShell workflows.
- [ ] Review, commit, push, open PR.

PR 2 (`feat/private-data-operations`, stacked on PR 1):
- [ ] Add separate loopback operator FastAPI app with dedicated ingestion credentials, server-side session authorization, CSRF/origin/host checks, bounded private upload storage and cleanup. Public API gains no privileged routes.
- [ ] Add private health/history/comparison and explicit dry-run, stage/review, confirm/publish workflow using existing pipeline. Never expose source HTML or event descriptions.
- [ ] Build dashboard using existing React controls/themes. Integrate root operator startup while preserving dev/check commands and existing database.
- [ ] Test privileged rejection, upload boundaries, no-write preview, atomic publication/retention, failure recovery, UI keyboard/accessibility; capture synthetic screenshots; open dependent PR.

Constraints: no intranet network access, credentials or private exports in git/logs/artifacts; no public republication; no database recreation. The provided fragment is inspection-only and must fail strict document validation. Prefer rejecting partial inventory imports to adding a new partial-publication lifecycle. Retarget/reverify PR 2 after PR 1 merges; never auto-merge.
